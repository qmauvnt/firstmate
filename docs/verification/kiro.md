# Kiro CLI worker verification

Audience: maintainer verification.

Verified 2026-10-08 on macOS arm64 with `kiro-cli 2.27.1`, on tmux and on a Herdr 0.9.3 lab session.
The [adapter reference](../../.agents/skills/harness-adapters/references/harness/kiro.md) owns operating facts; executable owners carry launch and state mechanics.
This verification covers crewmates and scouts only.
Primary, secondmate, ACP, Kiro hooks, and quota-provider integration are outside this guarantee.

## Refresh commands

```sh
kiro-cli --version
kiro-cli chat --help
kiro-cli chat --list-models --format json
bin/fm-test-run.sh tests/fm-kiro-harness.test.sh
FM_KIRO_SIGNALS_LIVE=1 bin/fm-test-run.sh tests/fm-kiro-signals-live-e2e.test.sh
```

The credentialed guard runs the actual command generated by `fm-spawn.sh` on a private tmux socket with the default model `claude-haiku-4.5` (`FM_KIRO_MODEL` overrides).
The pane keeps the real `HOME`, because Kiro's login lives in its per-user data store, so the turn markers it reads are the real host-wide directory.
Worktree allocation and initial endpoint delivery use the portable fixture; steering and lifecycle control then use the real backend and vendor process.
It skips when signed out or when the model is not listed; the shared live gate owns absent-tool and opt-in behavior.
Failures name the installed Kiro version.

## Busy source selection

Kiro writes one file per running turn into `~/Library/Application Support/kiro-cli/run/turn-markers` (macOS), named `<pid>-<turn_started_at_ms>.json`:

```text
{"pid":41720,"engine":"v2","session_interface":"interactive_cli","agent_mode":"default","turn_started_at_ms":1791449537383,"last_alive_at_ms":1791449537383,"version_full":"2.27.1","owner_started_at_s":1791449513}
```

The directory was empty while idle, held the file for the whole of a 24-second tool turn, and was empty again when the composer returned.
An Escape or Ctrl+C cancellation also removed it.
`<pid>` is the session's Bun engine (`.../kiro-cli/bun`), whose working directory stayed the launch directory, so firstmate binds a marker to a task through that process's cwd.
`last_alive_at_ms` did not advance during the 24-second turn, so it is not used as a heartbeat.
Setting `KIRO_TURN_MARKER_DIR` at launch did not move the files: Kiro exports that variable to its children but does not read it.
A sampled positional launch read `unknown` for about four seconds while the pane rendered `Initializing · type to queue a message`, `busy` for the whole turn, and `idle` within one sample of the composer returning; the source therefore requires the rendered idle placeholder before reporting idle.
The `--output-format stream-json` ACP stream was not chosen: it implies `--no-interactive`, which exits after one turn and leaves no steerable pane.
No hook surface was used: Kiro hooks live in an agent configuration under `~/.kiro`, which a worker launch would have to install globally.

## Observed vendor surfaces

`kiro-cli chat --trust-all-tools --model claude-haiku-4.5 "<question>"` in a fresh repository rendered no trust dialog and submitted the question itself.
The running composer row is `›  Kiro is working · <n>s · Type to steer · Ctrl+S to queue`, rendered in gray truecolor `38;2;158;158;158`, the same color as the idle placeholder `›  ask a question or describe a task ↵`; typed text uses the default foreground.
Both survive ghost stripping, so they are matched as rendered-only composer text.
A right-aligned `/copy to clipboard` row sits below the composer.
`/quit` opened the slash popup (`esc to cancel · ↵ to select`), and Enter exited with status 0 after printing `Session ended.` and `Resume with: kiro-cli --resume-id <session-id>`.
`kiro-cli chat --resume-id <id> "<question>"` answered from the prior conversation.
The shell tool environment carried `KIRO_VERSION=2.27.1`, `KIRO_SESSION_ID`, and `AWS_EXECUTION_ENV=AmazonQ-For-CLI Version/2.27.1 acp-client/kiro-tui`, and also an inherited `CLAUDECODE=1` from the launching Claude Code session.
`--effort max` and `--effort bogus` on `claude-haiku-4.5` both printed `[warn] failed to set effort '<value>': model does not support additional fields` and answered normally.
A cancelled `sleep 60` tool process kept running after the cancel and ended with the session.

## Herdr lab session

A named Herdr 0.9.3 lab session ran the same `fm-spawn.sh` launch command in a Herdr pane, with the task record pointed at that pane so `fm-send` and `fm-control` used the herdr backend:

```text
brief turn busy observed: 1
answer=80235 harness=kiro
settled: idle kiro-turn-marker
agent_state: alive
herdr agent get: {"agent":"kiro","agent_status":"idle",...}
composer: empty
steer=1147 acked=001.msg
idle interrupt rc=0 interrupt-delivered kiro-herdr harness=kiro backend=herdr verified=agent-alive cancel=unconfirmed
busy interrupt rc=0 interrupt-delivered kiro-herdr harness=kiro backend=herdr verified=agent-alive cancel=unconfirmed
after busy interrupt: idle kiro-turn-marker agent=alive
exit rc=0 stopped kiro-herdr harness=kiro backend=herdr ...
after exit agent=dead
```

Herdr recognizes the pane natively as agent `kiro`.
Its cursorless composer read first folded the `/copy to clipboard` row into the composer and answered `pending`; that row is now composer furniture, and the live pane then read `empty`, `pending` with a typed draft, and `empty` after clearing it.
Worktree allocation was the portable fixture rather than `treehouse get`.

On this host the Kiro desktop app's shell integration wraps every interactive zsh in a `zsh (kiro-cli-term)` pty proxy, and Herdr's process view of such a pane listed only that proxy, so the agent read `dead` and `fm-send` refused.
The lab panes therefore ran zsh with an empty `ZDOTDIR`; the wrapper affects any harness typed into a wrapped shell, not only Kiro.

## Coverage and limits

The portable regression drives the marker-before-`CLAUDECODE` order with ancestry blinded, anchored ancestry and liveness names against unrelated `kiro` and `kiro-cli-term`, the marker binding with real processes in different working directories, stale and foreign markers, the two-signal idle rule, rendered-only composer text on styled and unstyled reads, the cursorless hint-row boundary, delivery signals, and the worker-only launch with model and effort.
Zellij, Orca, and cmux were inspected through their backend-neutral capture, key, and composer surfaces, not live-tested.
The Linux turn-marker directory is unverified; an absent directory classifies `unknown`, never idle, and `FM_KIRO_TURN_MARKER_DIR` overrides the path.
